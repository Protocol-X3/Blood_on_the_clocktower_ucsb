## Judgment calls `[autonomy]`

- **A nomination moves through 提名中 → 计票中 → 计票完成 → closed.** The DM can correct locked votes until they close the vote (VOTE-08), and the count follows.
- **The threshold is fixed when the circle starts**, from the players alive at that moment.
- **Players may nominate themselves** (allowed in BotC). The warnings (NOM-02) count only votes that were held, not cancelled nominations.
- **The phase can't change while a nomination is open.** Once the DM confirms the day's execution (or 无人处决), no more nominations that day.
- **Executing a player who is already dead** records the execution without a second death.
- **A dead player's raised hand whose ghost vote the DM marked used** is locked as lowered.
- **The DM's screen drives the clock hand** (architecture.md). Each tick names the position it expects, so a repeated or stale tick never skips a seat, and a failed tick is retried.
- **Board:** posts only while the game runs; a deleted post is gone; the 其他 death note has at most 40 characters.
- **Summary page:** `/room/<code>/summary` shows the room's latest ended game. Roles are visible only to its players and DM (SECRET-03); M5 adds per-game history pages.
- **DM console layout:** the town square circle plus tabs 提名 / 座位 / 玩家 / 公告板. M4 turns it into the full grimoire with tokens and the log.
- **Bot sandbox:** the database functions exist in the shared Supabase project but work only while `private.app_config.bot_sandbox` is `on`. **The launch cleanup turns it off** and deletes the bot accounts. Bots are guest accounts named `机器人N-xxxx` (nicknames are unique), so they never have stats. The E2E suite runs against a sandbox build in `dist-sandbox/`, and the production build in `dist/` is scanned for sandbox code.

## Bugs caught

2. **While writing the offline test (VOTE-12):** the vote clock would have stopped for good after one failed tick until something else changed. It now retries, and the test covers it.
