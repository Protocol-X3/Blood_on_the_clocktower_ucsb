## Judgment calls `[autonomy]`

- **Public pages:** besides `/login`, the not-found page and the `/dev/design` gallery are public. Neither contains user data. Every app page requires sign-in (AUTH-07).
- **Taking the DM seat gives up your player seat** automatically, instead of refusing until you stand up (ROOM-09).
- **Leaving the room:** a seated player, or the DM, cannot leave the room while a game is running. Onlookers can.
- **Idle rooms:** they also close through a **pg_cron job every 10 minutes**. A refused join rolled back the lazy close; the tests caught this.
- **Sign-out is per device** (`scope: 'local'`), matching AUTH-06 ("ends the session on that device").
- **Test-account pool:** Supabase limits sign-ins to about 30 per 5 minutes per network. The tests therefore reuse pooled accounts with cached sessions, and their passwords are derived from the service-role key, never committed. The pool accounts (`e2e-pool-…@test.botc`) are removed in the launch cleanup.
- **Admin tests borrow the admin role.** Only one admin can exist, so during a local test run (about one minute) a pool account holds it. The E2E teardown always hands it back to your configured admin account, even after a failed run. `npm run db:set-admin` does the same by hand.

## Bugs caught by the tests

1. After a guest signed in, the login page refreshed the profile using a stale session snapshot, and the page hung on "载入中…". Fixed, and the profile loader now ignores out-of-order responses.
2. The idle-room close could be rolled back (see above). Fixed with the scheduled job.
