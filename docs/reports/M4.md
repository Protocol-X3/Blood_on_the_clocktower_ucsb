## Judgment calls `[autonomy]`

- **Tokens:** 中毒, 醉酒, any reminder of any role in the game's script, or custom text of up to 8 characters. Tokens are added and removed only while the game runs.
- **Tokens and the log become visible to the game's participants after it ends**, like the roles (SECRET-03). The rule text says the log appears in the summary and history; the tokens follow the same rule.
- **Log entries** belong to a seat or to the whole game (整局), with up to 500 characters. An edited entry keeps the phase it was written in. Entries are final once the game ends.
- **Mid-game role changes** (requirements.md): the DM picks any role from the game's script as the actual and the shown role, and two seats may now hold the same role (e.g. a second demon). Setup still keeps roles unique. The starting role is kept for stats (STATS-04).
- **The DM console** has tabs 提名 / 座位 / 玩家 / 日志 / 公告板. The grimoire is the circle on screens 1024 px wide or more, else a list.

## A failed first attempt

The first certification run failed one E2E check out of 146: a live-game page took more than 5 seconds to draw its heading late in the run (UI-03, a page-load wait, not a behaviour check). The unchanged rerun passed everything. The page-load wait is now 15 s (in the M5 branch), because a live game's first load makes several round trips to the shared free-tier database.

## Bugs caught

1. **CI caught a false alarm** in the secrecy test (TOKEN-02): after the end, the log is meant to be readable, and CI's faster run fetched it just after the end. The recorder now stops at the end of the game.
2. A test race: the DM added a log entry before the phase change had landed, so it was tagged with the old phase. The test now waits for the new phase. In real use, the button click completes before the DM can type.
